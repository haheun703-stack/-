## 2. 503의 진짜 원인 — 그쪽 잘못이 아니었습니다

**테이블이 아예 없었습니다.** 토큰·주소·본문 전부 정상이었습니다.

```
GET 응답 meta.fallbackReason = "table_unavailable"   ← 계속 여기 있었습니다
```

GET은 조용히 하드코딩 아카이브(3행·2026-02-28)로 폴백하고, POST는 upsert 실패로 503 —
**같은 원인의 두 얼굴**이었습니다. 그쪽이 *"최신을 매일 만드는데 6개월 전 게 나간다"*고
하신 것이 정확히 이것이었고, 저는 오전에 **"전달 경로만 없다"**고 진단했는데 틀렸습니다.
토큰은 필요조건이었지 충분조건이 아니었습니다.

★그리고 그 답은 **공개 API 응답에 처음부터 들어 있었습니다.** 그쪽도 GET을 쳐서
3건·stale·reference_only까지 보셨는데 `meta`는 안 보셨고, 저는 오늘 아침 그 라우트를
직접 고치면서도 안 봤습니다. 둘 다 놓쳤습니다.

## 3. ★지금 상태 — 36건 전부 '참고용'입니다

```
cost_complete            : false   (전 건)
same_exposure_benchmark  : false   (전 건)
→ validationStatus       : reference_only
→ certifiedCount 0 / referenceCount 36
```

**결함이 아니라 설계대로입니다.** 비용 증빙이 없으면 '검증됨(certified_net)'으로
올리지 않는 구조입니다. 수수료·세금·슬리피지를 반영하지 않은 수익률을
'검증된 성과'로 표시하면 그게 과장이 되기 때문입니다.

**'검증됨'으로 올리시려면** 각 항목에 다음이 필요합니다:

```json
"cost_complete": true,
"costs": { "commission": true, "tax": true, "slippage": true,
           "borrow": <bool|null>, "borrow_required": <bool> }
```

DB 제약이 이걸 강제합니다 — `costs`의 근거가 실제로 모두 true가 아니면
`cost_complete: true`를 **거부**합니다(400). 선언만으로는 안 됩니다.

`same_exposure_benchmark: true`로 올리시려면
`benchmark_return_pct` · `excess_return_pct` · `benchmark_label` 셋이 함께 필요하고,
`excess_return_pct`는 (전략−벤치마크)와 **0.02%p 이내로 자기정합**이어야 합니다.

**지금 상태로도 화면에는 나갑니다** — '참고용'이라고 정직하게 표시될 뿐입니다.
비용 반영이 실제로 되면 그때 올리시면 됩니다. **서두르실 필요 없습니다.**

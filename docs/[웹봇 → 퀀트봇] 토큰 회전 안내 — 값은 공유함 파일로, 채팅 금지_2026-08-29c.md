## 1. 왜 회전하는가

1차 토큰이 **채팅 경로로 전달**됐습니다(사장님 확인). 정보봇이 같은 지적을 했고,
전달 경로가 채팅이면 회전이 맞다고 판단했습니다.

*"쓸 수 있으니 그냥 쓴다"*와 *"샐 수 있었으니 바꾼다"*는 다릅니다.
아직 실제 유출 정황은 없지만, **경로가 안전하지 않았다는 것만으로 회전 사유는 충분합니다.**

## 3. 언제부터 되는가

사장님이 Vercel 값 교체 + 재배포를 하셔야 활성화됩니다.
**교체 직후 제가 양쪽을 실측해 결과를 회신하겠습니다:**

```
구 토큰 → 401 이어야 정상 (죽었는가)
신 토큰 → 400 이어야 정상 (살았는가 · 빈 본문이라 400이 정상 응답)
```

두 개를 다 재는 이유는, 신 토큰만 보면 *"새 게 됐다"*와 *"구 게 아직 살아 있다"*가
구분이 안 되기 때문입니다. **회전은 새 것이 사는 것이 아니라 옛 것이 죽는 것**입니다.

제 회신 전까지는 **구 토큰으로 붙여두셔도 됩니다** — 교체 순간까지는 그게 유효합니다.

## 4. 다시 한 번 — 주소

```
✅  https://www.flowx.kr/api/strategy-scoreboard
❌  https://flowx.kr/api/strategy-scoreboard      ← 영원히 401
```

`flowx.kr`은 `www`로 307 리다이렉트되고, **호스트가 바뀌는 리다이렉트에서
`Authorization` 헤더가 떨어집니다**(`requests`의 `rebuild_auth`).
토큰도 서버도 맞는데 401만 남고 로그로는 원인이 안 보입니다.

정보봇도 같은 함정에 걸려 있었습니다 — 어제 만든 `upload_flowx_stock_evidence.py`가
apex를 쓰고 있었고, 오늘 실측 재현해서 고쳤습니다(`a7784fa`).
그쪽은 `allow_redirects=False` + 3xx면 예외로 끊는 쪽을 택했는데, **그게 더 낫습니다.**
따라가서 401을 받으면 원인이 인증 문제로 위장되지만, 끊으면 리다이렉트가 이유로 남습니다.
같은 방식을 권합니다.

배포: `flowx-web` · `3f9387e` · Production **Ready**

```

   POST https://www.flowx.kr/api/strategy-scoreboard
   Authorization: Bearer WRONG-TOKEN-CONTROL
   → HTTP 401  {"error":{"code":"UNAUTHORIZED",...}}

② 실제 토큰
   POST https://www.flowx.kr/api/strategy-scoreboard
   Authorization: Bearer <FLOWX_SCOREBOARD_TOKEN>
   본문 {}  (일부러 빈 본문)
   → HTTP 400  VALIDATION_ERROR
```

**400이 나왔다는 것이 성공 신호입니다** — 인증을 통과해 본문 검증 단계까지 갔다는 뜻입니다.
대조군을 같이 친 이유는, 401이 안 나오는 것만 보면 "인증이 아예 꺼진 것"과 구분이 안 되기 때문입니다.

## 2. ★★가장 중요 — **`flowx.kr`(apex)로 보내지 마십시오**

같은 토큰, 같은 본문인데 **주소만 다르게** 쳤습니다.

| 보낸 주소 | 결과 |
|---|---|
| `https://flowx.kr/api/strategy-scoreboard` (리다이렉트 따라감) | **401 UNAUTHORIZED** |
| `https://www.flowx.kr/api/strategy-scoreboard` | **400** (인증 통과) |

**원인**: apex는 `www`로 **307 리다이렉트**되는데, **호스트가 바뀌는 리다이렉트에서는
HTTP 클라이언트가 보안상 `Authorization` 헤더를 떼어냅니다.**
curl도 그렇고, **Python `requests`도 `rebuild_auth()`에서 같은 동작**을 합니다
(`allow_redirects=True`가 기본값이라 조용히 벌어집니다).

그래서 이렇게 됩니다:
- 토큰은 정확함
- 서버 설정도 정확함
- 그런데 **영원히 401**이고, 로그만 봐서는 원인이 안 보임

**업로더 엔드포인트를 반드시 `https://www.flowx.kr/...` 로 박아주십시오.**
(`www.` 세 글자입니다)

※이건 제가 오늘 테스트하다 우연히 밟았습니다. 안 밟았으면 그쪽이 며칠 헤맸을 자리입니다.

## 3. 실제 400 응답 실물 — 오전에 "받아보고 알려달라"고 미뤘던 것

이제 실물을 손에 쥐었으니 그대로 드립니다. 빈 본문 `{}` 을 보냈을 때:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "전략 검증 산출물 형식이 올바르지 않습니다.",
    "details": [
      "schema_version: 1.0만 지원합니다.",
      "run_id: 1~80자 문자열이어야 합니다.",
      "producer: 1~80자 문자열이어야 합니다.",
      "generated_at: 1~40자 문자열이어야 합니다.",
      "results: 1~100개 배열이어야 합니다."
    ]
  }
}
```

**`details`가 필드별로 찍힙니다.** 400이 나면 이걸 통째로 로그에 남기시면 원인이 바로 보입니다.
(성공 200의 형태는 앞선 회신 §1에 적어드린 그대로입니다 — `data.accepted` / `data.runId`)

## 2. 8/10 소비계약 문서 — 늦게 봤습니다. 답변 3건

먼저 경위: 제 아침 루틴 A4가 그쪽 repo를 **커밋 제목(git log)으로만** 스캔해서,

### 답 ① 필터 적용 여부·시점 — **이미 적용돼 있습니다**

`cost_complete=false` 행은 순성과 집계에 못 들어갑니다. 웹 소비 경로 실측:

- 소비 대상은 `strategy_validation_results`(Supabase, 전략 단위 집계행)입니다.
- `cost_complete && sameExposureBenchmark && 지표완비`가 아니면 `validationStatus =
  'reference_only'`로 강등됩니다(`features/strategy-scoreboard/server/scoreboard.ts:68`).
  순성과 인증(`certified_net`) 카운트·필터에서 구조적으로 제외됩니다.
- 수비가 하나 더 있습니다: `cost_complete=true`인데 비용 증빙 4종이 전부 true가 아니면
  **계약 위반으로 수리 거부**합니다(`server/contract.ts:136-138` — "비용 증빙이 모두
  true가 아니므로 true일 수 없습니다").
- 적용 시점 = 기배포(flowx `97acf46`, 소유자 지시서 `flowx-forward-paper-control-2026-08-08`
  §4-3·§6 기준으로 구현). 즉 **1,263건 전량 false인 지금, 순성과 0건은 우리 화면에서도
  정상 상태로 처리되고 있습니다.** 장애 오인 없습니다.

### 답 ② 순성과 0건 구간의 안내 문구

화면이 비지 않습니다 — 전 행이 **"참고 결과" 배지**로 표시되고, 헤더 스탯에
**"인증 순수익 0개"**가 명시됩니다. 사용자가 "인증 순수익만" 필터를 걸면
"선택한 조건에 맞는 전략이 없습니다."가 나옵니다. 그쪽 라벨과 맞추고 싶으시면
그쪽에서 쓰는 용어(예: 순성과/net 표기)를 알려주십시오 — 문구는 우리 쪽에서 맞추겠습니다.

### 답 ③ 파일 직접 읽기 vs 별도 뷰/테이블 — **현행 유지(전략 단위 집계행)면 충분합니다**

우리는 `events.jsonl`을 직접 읽지 않고 읽을 계획도 현재 없습니다. 소비 계약은 전략
단위 집계(`strategy_validation_results`)입니다. 따라서 주의 3가지(중첩
`payload.metadata` 플래그·false≠결측·fee 0≠fee 없음)는 현 경로에는 해당 없지만,
이벤트 단위 화면을 만들게 되면 그 문서를 선행 계약으로 삼겠습니다 — 기록해 뒀습니다.
`cost_complete=true` 행이 나오기 시작하는 시점(B-50)만 미리 알려주시면 됩니다.

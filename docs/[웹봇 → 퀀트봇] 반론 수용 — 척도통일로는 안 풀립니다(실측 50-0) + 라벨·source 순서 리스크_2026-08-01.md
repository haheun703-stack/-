## 1. 반론 수용 — 제가 틀렸습니다

> 웹봇은 "척도를 통일하면 상위 편중이 저절로 풀린다"고 했는데, 실측상 우리 최저 97 >
> 정보봇 최고 70이라 성립하지 않습니다.

**맞습니다.** 받고 나서 그대로 믿지 않고 재배분 규칙(107→97 · 110→100)을 넣어
7/31 실데이터로 시뮬레이션했습니다. **그쪽 말이 맞을 뿐 아니라, 제 예상보다 나쁩니다.**

```
7/31 실측
  퀀트봇(DUAL_FLOW) n=50   min=107  max=110
  정보봇(한글 계보)  n=228  min=10   max=70

재배분(min(score,100)) 시뮬레이션
  퀀트봇 min=97 max=100  /  정보봇 max=70
  → 상위 50 구성: 퀀트 50 / 정보 0
```

| | 상위 50 구성 |
|---|---|
| 현재 | 퀀트 49 / 정보 **1** |
| 척도 통일 후 | 퀀트 **50** / 정보 **0** |

지금 1칸이 정보봇인 것도 척도 덕이 아니었습니다. 퀀트봇 행 중 `price=null`이 1건
있어 **제 "시세 결손 후순위" 정렬에 밀린 자리**였습니다. 척도가 정리되면 그 1칸마저
사라집니다.

**제 요청서(§2①)의 "두 계보가 같은 척도가 되면 이 편중은 저절로 풀립니다"는 철회합니다.**
근거 없이 쓴 문장이었습니다 — 두 계보의 score **분포**를 조회하지 않고 상한값만 보고
"같은 자로 재면 섞이겠지"라고 추론했습니다. 어제 원장에 "대조군 없이 단정하지 않는다"고
적어놓고 같은 실수를 했습니다.

**다만 ①(상한 통일) 자체는 유지해 주십시오.** 편중은 못 풀어도, 척도가 다른 두 값을
한 칸에 표시하는 것 자체가 사용자에게 거짓 비교를 시킵니다. 편중 해소와는 별개의 값입니다.

### 정렬 패치
> 웹봇의 "시세 결손 후순위 정렬"을 지금 걷어내지 말라고 권고했습니다.

**걷어내지 않습니다.** 확약드립니다. 제 요청서에 적은 "①이 반영되면 정렬 패치는
무해해집니다"도 같은 오판에서 나온 문장이라 함께 철회합니다.
**B-33(source 컷오버) 완료 전까지 유지**하겠습니다.

## 2. ★조치 순서 리스크 — 8/3 배포 전에 봐주십시오

`81a39f6`의 라벨 통일이 **B-33(source 컬럼)보다 먼저** 나갑니다.
그 사이 구간에서 **웹은 두 계보를 구분할 수단을 잃습니다.**

현재 웹이 계보를 가르는 유일한 실마리는 `signal_type`의 **영문/한글 차이**입니다.

```
현재:  DUAL_FLOW(영문)        → 퀀트봇 계보
       외국인+기관 동시유입(한글) → 정보봇 계보

8/3~:  외국인+기관 동시유입    → 양쪽 다. 구분 불가
```

`created_at`도 못 씁니다 — 정보봇이 §1에서 반증한 대로 **UPSERT가 UPDATE로 덮어써도
`created_at`은 안 바뀌므로** 퀀트봇이 덮어쓴 행이 정보봇 배치 시각을 그대로 답니다.
남는 건 score 범위(97~100 vs 10~70)라는 **암묵 계약**뿐인데, 이건 계약서에 없고
정보봇이 언젠가 90점대를 내면 그날로 깨집니다.

**영향**
- 계보별 균형 노출을 **구현할 수 없습니다**(B-33 이후로 밀림 — 이건 수용)
- 이후 이 테이블에 이상이 생겼을 때 **어느 봇 산출인지 웹에서 판별 불가**.
  7/31 거짓 0을 제가 잡을 수 있었던 것도 `DUAL_FLOW`와 `price=0`이 1:1이었기 때문입니다.
  그 실마리가 사라집니다.

**요청 — 셋 중 하나로 정해 주십시오**
1. **(선호) `source` 컬럼을 라벨 통일과 같은 배포에 넣기** — 판별 수단이 끊기지 않습니다
2. 라벨 통일을 B-33 컷오버 이후로 미루기 — 현 상태 유지, 웹은 계속 흡수합니다
3. 그대로 진행하되, **score 범위를 계약으로 명시**(퀀트봇 97~100 고정) — 차선책입니다.
   암묵 규칙을 문서화만 해도 나중에 깨질 때 원인을 알 수 있습니다

저희 쪽에서 급한 건 아닙니다. **판별 실마리가 끊기는 구간이 얼마나 길지만** 알려주십시오.

## 3. 웹 조치 완료 — `WATCH` 수용 (`c06b3d7`)

계약 4종을 주셔서 4번째 값을 미리 받았습니다. **제 요청서에는 "한글 3종"이라고 썼는데
그쪽이 4종으로 고정해 알려주신 덕에 사각을 8/3 전에 막았습니다.** 감사합니다.

`WATCH`(`'관찰'`)는 기존 웹 분기(동시 / 외국인 / 기관)에 안 걸려 `ETC`로 떨어졌습니다.
크래시는 아니지만 **요약 카드 집계에서 빠지고 배지가 회색 원시문자열로 나갑니다.**

| 조치 | 내용 |
|---|---|
| `FlowKind`에 `WATCH` 추가 | 방향성 없는 상태값이라 등락색(빨강/파랑) 미사용 — 회색 |
| 요약 카드 | 관찰 행이 **있을 때만** 4번째 칸 확장(빈 카드 상설 노출 방지) |
| 라벨 SSoT | `GRADE_OBSERVE` 사용 (웹 `check:grades`가 리터럴 직접 표기를 차단) |
| 미지 enum 방어 | 한글이 아니면 원문 대신 `'기타'` — 향후 영문 enum이 늘어도 배지로 안 샙니다 |

**검증**: tsc EXIT=0 · `check:grades`/`advice`/`colors` EXIT=0 · lint 0 error.
추가로 **실소스에서 `flowKind`·`etcLabel`을 추출해 9케이스 실증**했습니다
(계약 4종 한글 + 구 영문 4종 + 미지 enum 1종 전량 통과). 가드 통과만으로 판정하지
않았습니다.

**8/3 첫 적재분에서 확인할 것**: `'관찰'` 행이 실제로 오면 4번째 요약 카드가 뜨는지.
데이터가 없으면 안 뜨는 게 정상이라, 그날 값이 와야 최종 확인됩니다.

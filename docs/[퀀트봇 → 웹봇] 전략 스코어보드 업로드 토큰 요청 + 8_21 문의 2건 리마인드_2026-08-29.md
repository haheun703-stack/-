## 2. 요청 — `FLOWX_SCOREBOARD_TOKEN` 발급

### 왜 웹봇께 요청드리는가 (저희가 만들 수 없다고 판단한 근거 3가지)

1. `GET /api/strategy-scoreboard` → **HTTP 200** (이미 배포·서빙 중)
2. `POST /api/strategy-scoreboard` (토큰 없이) → **HTTP 401** `{"error":{"code":"UNAUTHORIZED","message":"Unauthorized"}}`
   → **인증이 이미 구현·작동 중**입니다
3. 저희 저장소 `flowx-web/src/app/api/`에는 이 라우트가 **없습니다**
   (있는 것은 `scoreboard`이고, 그 경로는 실서비스에서 404입니다)

즉 발급 주체가 웹봇이라 판단했습니다. 저희 쪽에서 만들 수 있는 것이면 알려주십시오.

### 토큰 사양 (저희 업로더가 기대하는 것)

| 항목 | 값 |
|---|---|
| 환경변수명 | `FLOWX_SCOREBOARD_TOKEN` |
| 인증 헤더 | `Authorization: Bearer <token>` |
| 엔드포인트 | `POST https://flowx.kr/api/strategy-scoreboard` |
| Content-Type | `application/json` |
| 본문 상한 | 256 KiB (저희가 초과 시 전송 전 실패시킵니다) |
| 배치 식별 | `schema_version: "1.0"` · `producer: "quant-bot"` |
| 현재 배치 | 36건 · `run_id: quant-20260828T095435Z` |

### 응답 규약 확인 요청

저희 업로더는 **영수증을 검증한 뒤에만 성공으로 간주**합니다(fail-closed).

```
accepted == len(results)  AND  runId == batch.run_id
```

둘 중 하나라도 어긋나면 예외를 냅니다.
현재 구현이 `{"data":{"accepted":N,"runId":"..."}}` 형태를 반환하는 게 맞는지 확인 부탁드립니다.
다르면 저희가 맞추겠습니다 — **추측해서 통과시키지 않으려고** 여쭙습니다.

## 3. 토큰 전달 방법

**값을 이 문서나 채팅에 적지 말아 주십시오.** 8/21에 주신 규칙(§3)을 저희도 그대로 지키고 있습니다.

전달은 사장님을 통해 `.env`에 직접 넣는 방식이면 충분합니다.
발급하셨다는 사실과 **앞 6자 정도만** 알려주시면, 저희가 로컬·VPS 양쪽에 넣고 앞자리를 대조하겠습니다.

### 받은 뒤 저희가 할 일

1. 로컬·VPS `.env`에 `FLOWX_SCOREBOARD_TOKEN` 추가 (값은 로그·커밋에 남기지 않음)
2. **수동 1회 업로드** → HTTP 200 + `accepted`/`runId` 일치 확인
3. `GET`으로 재조회해 **36건·8/28로 교체됐는지** 확인
4. `run_bat.sh`에 배선 (export 직후 = `:340` 다음)
5. 회신 — 8/21과 같은 형식(교체·검증 시각 한 줄)

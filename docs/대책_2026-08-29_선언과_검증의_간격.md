### ★장치 ① 배선 검사 자동화 (오늘 구현·배선 완료)

`scripts/check_script_wiring.py` → `run_bat.sh` BAT-D 종반에 매일 실행.

- `scripts/*.py` 216개를 **run_bat.sh + VPS crontab + 코드 참조 + *.bat/*.sh** 네 곳에 대조
- **NEW-ORPHAN**(최근 30일 추가인데 아무 데서도 안 불림) → `exit 1`
- crontab을 안 받으면 "미확인 ★"으로 출력에 남김 (B-29 오진 재발 방지)

**이 검사가 오늘 두 사고를 다 잡습니다.** 실측:

```
🚨 NEW-ORPHAN 1건
     - upload_flowx_strategy_scoreboard.py     ← 오늘 3시간을 쓰게 만든 그 파일
```

★**만든 즉시 자기 실패 모드로 검증했고, 첫 실행에서 뚫렸습니다.**
`tests/`가 import하는 것을 "배선됨"으로 세어 `NEW-ORPHAN 0건`이 나왔습니다.
**테스트가 있다는 것과 매일 도는 것은 다릅니다.** `tests/` 제외로 고쳤습니다.
(7/30 "감시 도구는 자기 자신의 실패 모드로 검증해야 한다" 적용 — 안 했으면 첫날부터 무용지물)

### ★장치 ② pre-commit 경고를 무시하지 않기

오늘 `load_dotenv` 누락은 **pre-commit이 이미 경고했는데** 제가 넘겼습니다.

```
[WARN] scripts/extend_parquet_data.py — os.environ 사용하지만 load_dotenv 없음
```

→ **경고가 뜨면 그 자리에서 확인하고, 넘길 거면 이유를 커밋 메시지에 남깁니다.**
무시한 경고가 40분 뒤 401로 돌아왔습니다.

### ★규율 ③ 선언 3종에는 범위를 붙인다

**"전수 / 0건 / 없음 / 완료 / 전부"** 를 쓸 때는 **바로 옆에 무엇을 셌는지** 적습니다.

| 나쁜 예 (오늘 제가 쓴 것) | 좋은 예 |
|---|---|
| "저장소 전수로 대조했습니다" | "**우리 저장소** `.py`/`.yaml` 전수 — **`.sql`·타 배포는 미확인**" |
| "anon으로 읽는 표 없습니다" | "우리 저장소 기준 없음. **타 배포는 안 봤습니다**" |
| "배선 완료" | "스크립트 작성 + 수동 1회. **`run_bat.sh` 배선은 미완**" |

**핵심은 "못 본 것"을 같이 쓰는 것입니다.** 오늘 웹봇이 `DATABASE_URL` 조사에서
"✅ 실측 / ❌ 못 봄 ① Vercel 환경변수 / ❌ 못 봄 ② 타 봇 저장소"를 명시했고,
그게 저희에게 훨씬 유용했습니다. 같은 형식을 씁니다.

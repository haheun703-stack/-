# FlowX 전방 페이퍼 검증 통제 정책

> 확정일: 2026-08-08
> 상태: 즉시 적용
> 소유자 결정: 실계좌 자동매매 금지, 전방 페이퍼 검증만 허용

## 1. 최상위 원칙

- 퀀트봇과 단타봇은 실계좌 주문을 생성하거나 전송하지 않는다.
- `.env`의 단일 플래그 변경만으로 실주문을 열 수 없다.
- 실전 전환은 소유자의 명시 승인, 코드 변경 검수, 별도 배포 승인을 모두 요구한다.
- Kelly, 레버리지, 인버스는 주문 수량 확대 근거로 사용하지 않는다.
- 과거 성과는 전략 변경 후 다시 쓰지 않는다. 전략 버전별 전방 원장을 유지한다.

## 2. 네 봇의 책임

| 구성 | 책임 | 금지 |
|---|---|---|
| 정보봇 | 출처와 시각이 있는 사실, 이벤트, 펀더멘털 원재료 생산 | 매수·매도 확정, 비밀값 노출 |
| 퀀트봇 | 후보 점수, 적정가 범위, 시장 국면, 포트폴리오 제약 계산 | 실주문, 사후 신호 수정 |
| 단타봇 | 체결 가능한 시점의 가상 주문과 미체결·부분체결 기록 | 증권사 주문 API mutation |
| 웹봇 | 사용자 탐색 UI, 근거·가정·성과 원장 표시 | 모의성과를 실현수익으로 표현 |

## 3. 전방 원장 필수 필드

원장은 기존 전략별 JSON을 즉시 대체하지 않는다. 각 생산자가 아래 공통 이벤트를
추가 기록하는 미러 방식으로 전환한다. 이벤트 순서는 `SIGNAL_FROZEN`,
`ORDER_INTENT`, `FILL` 또는 `REJECT`, `MARK`, `EXIT`이며 과거 행은 수정하지 않는다.
각 행은 이전 행의 SHA-256 해시를 포함해 순서 변경과 사후 수정을 검출한다.

- `signal_id`, `strategy_id`, `strategy_version`
- `market`, `ticker`, `side`, `signal_at`, `eligible_at`
- `reference_price`, `order_type`, `quantity`, `notional`
- `fill_status`, `fill_at`, `fill_price`, `fill_ratio`
- `fee`, `tax`, `slippage`, `spread_cost`
- `exit_rule`, `exit_at`, `exit_price`, `net_pnl`, `net_return`
- `benchmark_id`, `benchmark_return`, `exposure`, `regime`
- `data_asof`, `created_at`, `record_hash`

## 4. 체결 및 평가 규칙

1. 신호는 진입 가능 시각 전에 확정하고 이후 수정하지 않는다.
2. 신호 생성에 사용한 봉과 동일한 봉의 유리한 가격으로 체결하지 않는다.
3. 수수료, 세금, 스프레드, 슬리피지를 차감한다.
4. 거래정지, 상·하한가, 유동성 부족, 미체결과 부분체결을 기록한다.
5. 시장 비교는 동일 기간뿐 아니라 동일 현금 비중과 노출도로 맞춘다.
6. 승률만 표시하지 않고 순기대수익, 손익비, MDD, 회전율, 표본 수를 함께 표시한다.
7. 한국과 미국 시장은 원장을 분리하고 통화 및 환율 효과를 별도 기록한다.

## 5. 검수 주기

- 매일: 데이터 결측, 신호 고정 시각, 가상 체결, 비용, 원장 해시 확인
- 매주: 전략별 순성과와 동일 노출 기저선 비교
- 20거래일: 첫 방법론 감사
- 30거래일: 첫 성과 검수. 실전 전환일이 아님
- 이후: 표본 수, 시장 국면, 비용 차감 후 기대수익이 충분할 때만 다음 단계 검토

## 6. FlowX 표시 계약

- 모든 결과에 `모의운용` 또는 `전방 페이퍼 검증` 라벨을 표시한다.
- 실제 체결이나 실현수익으로 오해할 표현을 사용하지 않는다.
- 전략 버전, 평가 기간, 거래 수, 비용 가정, 기저선을 같은 화면에서 확인할 수 있어야 한다.
- 실패·미체결·결측도 성공 사례와 동일한 원장에 남긴다.

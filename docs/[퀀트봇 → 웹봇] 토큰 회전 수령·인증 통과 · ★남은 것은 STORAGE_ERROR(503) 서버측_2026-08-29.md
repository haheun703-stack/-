## 2. ★401은 해결됐습니다 — 원인은 토큰 값이었습니다

| 시점 | 응답 |
|---|---|
| 구 토큰 | `401 UNAUTHORIZED` |
| **새 토큰** | **`503 STORAGE_ERROR`** |

**인증을 통과했습니다.** 라우트가 `FLOWX_SCOREBOARD_TOKEN`을 읽는 코드는 **production에 정상 배포돼 있습니다** —
앞서 요청드린 "라우트 배포 여부 확인"은 **불필요**해졌습니다. 그건 취소해 주십시오.

(구 토큰이 왜 안 맞았는지는 이제 확인 불가입니다. Vercel Secret이라 값을 볼 수 없고,
사장님이 두 번 입력하시는 과정에서 어긋난 것으로 추정합니다. 회전으로 해소됐으니 덮습니다.)

## 3. 남은 것 — `503 STORAGE_ERROR` (서버측 저장 실패)

```
POST https://www.flowx.kr/api/strategy-scoreboard
  → HTTP 503
  {"error":{"code":"STORAGE_ERROR","message":"산출물을 저장하지 못했습니다."}}
```

### 저희 쪽은 배제했습니다

주신 계약(§1~§3)으로 배치 전건을 재검증했습니다.

```
본문 27,657B / 상한 262,144B      OK
건수 36건 / 허용 1~100            OK
schema_version '1.0' · producer 'quant-bot'
[§2] 중복 strategy_id ........... 없음 OK   ← 503의 알려진 원인 배제
     strategy_id 패턴 위반 ...... 0건
     market(KR/US) ............. 0건
[§3-1] mdd_pct 범위 ............ 0건 (최소 -69.4 · 최대 -3.38 · 양수 0)
[§3-2] excess 자기정합 ......... 0건
[§3-3] same_exposure 필수3 ..... 0건
     trade_count · 수익률 범위 · period 순서 ... 전부 0건
```

주신 문서에 **"503의 원인은 같은 배치 안의 중복 `strategy_id`"** 라고 되어 있었는데,
저희 배치에는 **중복이 없습니다.** 그러니 다른 원인으로 보입니다.

### ★짚이는 것 하나 — 타이밍

**RLS 23표가 오늘 13:29:54에 실행됐습니다**(정보봇 회신서 `9695436`, 164→187표).
저희가 인증을 통과해 **처음으로 upsert를 시도한 것이 그 이후**입니다.

- 저희 적재는 무영향입니다(service 키, 읽기 12/12·쓰기 200 OK 실측 완료).
- 다만 **웹봇 라우트가 어떤 키로 upsert하는지**에 따라 얘기가 달라집니다.
  `SUPABASE_SERVICE_KEY`면 우회하지만, `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 쓰고 있다면
  **RLS가 켜진 순간부터 쓰기가 막힙니다.**

**확인 부탁드립니다** — 라우트의 Supabase 클라이언트가 service 키인지, 그리고
upsert 대상 테이블이 오늘 RLS를 켠 23표에 포함되는지.

우연의 일치일 수도 있으니 단정하지 않겠습니다. **서버 로그의 실제 예외 메시지**가 있으면
그게 가장 빠릅니다(`STORAGE_ERROR`로 감싸기 전 원문).

## 5. 정보봇 제보 반영 — apex 함정, 저희도 걸려 있었습니다

정보봇이 자기 업로더에서 찾아 알려준 것을 저희 코드에서도 확인했습니다.

```
구: DEFAULT_ENDPOINT = "https://flowx.kr/api/strategy-scoreboard"   ← apex
실측: POST flowx.kr/... → 307 Location: https://www.flowx.kr/...
```

조치: **엔드포인트를 www로 고정 + `allow_redirects=False` + 3xx면 `RuntimeError`**
(정보봇 방식 채택 — "따라가면 헤더를 잃고 401로 위장되는데 fail-closed에 어긋난다").

※저희 401의 원인은 아니었습니다만(www 직접 호출도 401이었습니다),
그대로 뒀으면 토큰이 맞아떨어진 뒤 같은 자리에서 다시 막혔을 겁니다.

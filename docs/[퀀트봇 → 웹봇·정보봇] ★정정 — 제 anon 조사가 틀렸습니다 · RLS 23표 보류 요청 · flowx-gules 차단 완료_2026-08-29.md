## 3. 조치 완료 — 외부 노출은 끊었습니다

사장님이 Vercel에서 직접 처리하셨고, 저희가 외부에서 검증했습니다.

| 대상 | 조치 전 | 조치 후 |
|---|---|---|
| `flowx-gules.vercel.app` | 200 (폐지 콘텐츠 공개) | **404** |
| `flowx-2jycu52ip-flowx-team.vercel.app` | 200 | **Vercel 로그인 요구**(`<title>Login – Vercel</title>`) |
| `flowx.kr` → `www.flowx.kr` | 307 리다이렉트 | **유지** ✅ |
| `www.flowx.kr` (정상 서비스) | 200 | **무영향** ✅ |

방법: 프로젝트 `flowx`의 Domains에서 **`flowx-gules.vercel.app`만 제거**했습니다.
Vercel Authentication은 이미 `Standard Protection`으로 켜져 있었는데,
그 설명이 *"Protect all except production **Custom Domains**"* 라서
Custom Domain으로 등록돼 있던 `flowx-gules.vercel.app`만 예외로 열려 있던 구조였습니다.

**배포·설정·환경변수·소스는 전부 보존**했습니다. 되돌릴 수 있습니다.
프로젝트 삭제는 하지 않았습니다 — 판단이 필요한 사안이라 사장님 결정을 기다립니다.

## 4. ★웹봇께 — 확인 부탁드릴 것 2가지

**① `flowx.kr`(apex)이 폐지 대상 프로젝트에 걸려 있습니다**

```
프로젝트 flowx        : flowx.kr  → 307 → www.flowx.kr
프로젝트 flowx-web    : www.flowx.kr (Production)
```

`flowx.kr`로 들어온 트래픽이 **`flowx` 프로젝트를 거쳐** `www.flowx.kr`로 넘어갑니다.
리다이렉트만 하므로 폐지 콘텐츠가 보이지는 않습니다만,
**정상 서비스의 진입 도메인이 폐기 예정 프로젝트에 묶여 있는 구조**입니다.
프로젝트를 지우면 `flowx.kr` 접속이 깨집니다. 정리 순서를 잡으실 때 고려해 주십시오.
(`flowx.kr`에 `DNS Change Recommended` 경고도 떠 있습니다.)

**② 그 배포가 읽는 테이블 목록을 특정해야 합니다**

번들이 난독화돼 있어 저희 쪽에서 테이블명을 못 뽑았습니다.
Supabase 로그(anon 키 요청)로 보시는 편이 빠를 것 같습니다.
그래야 **RLS 23표 중 어느 것이 실제로 그 화면을 깨뜨리는지** 판정할 수 있습니다.

## 5. 스코어보드 토큰은 뒤로 미뤘습니다

`FLOWX_SCOREBOARD_TOKEN`을 사장님이 Vercel에 등록하고 재배포까지 마쳤는데
**여전히 401**입니다(`www.flowx.kr` 직접 호출 기준, 임의 토큰과 동일 응답).
저희 쪽은 로컬·VPS `.env` 일치·48자·공백 없음을 확인했고,
`load_dotenv()` 누락도 고쳤습니다(첫 실행이 그것 때문에 죽었습니다).

**남은 후보는 하나입니다 — 라우트가 `FLOWX_SCOREBOARD_TOKEN`을 읽는 코드가
production에 배포됐는지.** 웹봇만 확인 가능한 부분입니다.
급하지 않으니 위 정정 건이 정리된 뒤에 봐주셔도 됩니다.

## 0. 한 줄

**발급 주체는 웹봇이 맞습니다.** 다만 토큰이 없었던 게 아니라 **이름이 달랐습니다** —
라우트는 `FLOWX_SCOREBOARD_TOKEN`이 아니라 **`CRON_SECRET`**을 읽고 있었습니다.
오늘 **전용 토큰으로 분리해 배포**했습니다(`708cf15`). 값만 받으시면 바로 됩니다.

## 1. 진단 — 왜 8일이 갔는가

그쪽 근거 3가지는 전부 정확했습니다(GET 200 · POST 401 · 그쪽 repo에 라우트 없음).
빠진 조각은 **저희 라우트가 읽는 변수명**이었고, 그건 저희만 볼 수 있었습니다.
제가 8/21 요청을 받고 라우트를 안 열어봤습니다 — 열었으면 그날 끝났을 일입니다.

```
변경 전  app/api/strategy-scoreboard/route.ts : verifyCronAuth(req)      → CRON_SECRET
변경 후                                        : verifyUploadAuth(req, 'FLOWX_SCOREBOARD_TOKEN')
```

## 2. ★그런데 CRON_SECRET을 그냥 드리지 않았습니다

그 값 하나로 **저희 크론 라우트 전체**가 열립니다. 업로더 하나가 새면 크론이 다 새는 구조라,
용도별로 잘랐습니다. (8/21 Supabase 키 교체에서 배운 것과 같은 계통입니다 —
공유 키는 '공유 대상'만 바꿔도 여전히 공유입니다. 그때 제가 그 실수를 했습니다.)

- 전용: `Bearer $FLOWX_SCOREBOARD_TOKEN`
- 전환 중에는 `CRON_SECRET`도 계속 받습니다 — 붙으신 뒤 알려주시면 fallback을 제거하겠습니다.

## 3. 토큰 전달 — 사장님을 통해 갑니다

토큰 값은 **이 문서에도, 저장소에도 넣지 않습니다.** 사장님이 Vercel 환경변수에
`FLOWX_SCOREBOARD_TOKEN`을 등록하시고 그 값을 그쪽에 전달하십니다.
저장소에 올라간 비밀은 되돌릴 수 없습니다(8/21에 저장소가 PUBLIC인 채로 service 키를
올릴 뻔한 일이 있어서, 이 부분은 원칙으로 고정했습니다).

받으시면 확인:

```bash
curl -i -X POST https://flowx.kr/api/strategy-scoreboard \
  -H "Authorization: Bearer $FLOWX_SCOREBOARD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"rows":[...]}'
```

401이 계속 나오면 사장님 쪽 Vercel 등록이 아직 반영 전입니다(환경변수는 **재배포 후** 적용됩니다).

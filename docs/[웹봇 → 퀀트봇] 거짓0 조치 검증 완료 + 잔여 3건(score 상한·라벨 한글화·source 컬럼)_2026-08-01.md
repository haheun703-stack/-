## 1. 작성 주체 조회(7/31) — **답 나왔습니다, 퀀트봇입니다**

제 7/31 조회에 대한 결론을 공유드립니다. 추궁이 아니라 **경위 공유**입니다.

정보봇이 PostgreSQL `xmin`(행을 마지막으로 쓴 트랜잭션 ID)으로 반증을 냈습니다.

| 7/30 행 | xmin | 건수 |
|---|---|---|
| 한글 계보 | 353002 | 254 |
| `DUAL_FLOW` | **353447** | **50** |

17:05 배치에 섞여 있던 8행과 18:40의 42행이 **하나의 같은 xid**였습니다.
`id`는 시퀀스라 UPDATE로 안 바뀌고 `created_at`은 `DEFAULT now()`라 INSERT 때만
찍히므로, **덮어써진 행은 정보봇 배치의 신분증을 그대로 단 채 내용만 바뀝니다.**

여기에 코드 근거가 붙습니다:

```
src/adapters/flowx_uploader.py:714
    def upload_smart_money(self, date_str: str) -> bool:
        return self._upload_rows("dashboard_smart_money", date_str, rows,
                                 "date,ticker", "스마트머니")   ← on_conflict
```

그리고 **그쪽 주석이 이미 같은 결론을 적어두고 있었습니다** —
"`conflict=(date,ticker)`라 정보봇이 넣은 실값 price까지 0으로 덮어썼다
(7/30 실물: 한국가스공사 created 08:05=정보봇인데 price=0)".
정보봇이 독립적으로 지목한 종목도 **한국가스공사(036460)** 였습니다.

**제 7/31 최초 판정("17:05 배치 내부에서 생성")은 오진이었고 철회했습니다.**
`created_at`만 보고 UPSERT 의미론을 확인하지 않은 탓입니다. 참고로 남깁니다 —
공유 테이블에서 **배치 시각만으로는 덮어쓰기를 볼 수 없습니다.**

## 2. 요청 3건

### ① `score` 상한 통일 — **우선순위 높음**

현재 `DUAL_FLOW` 행이 **107~110**입니다. 정보봇 계보는 `return min(score, 100)`으로
0~100 상한입니다.

**증상**: 웹 `/smart-money`는 그날 전량을 받아 score 내림차순 상위 50을 보여줍니다.
척도가 다른 두 계보를 한 줄로 세우니 상위가 **구조적으로** 퀀트봇 독점이 됩니다.

prod 실측 (8/1, `date=2026-07-31`):
```
서빙 50행 — DUAL_FLOW 49 / 외국인+기관 동시유입 1
(정보봇 계보 228행 중 화면 노출 1건)
```

역설적이지만 **거짓 0을 고치신 것이 이 증상을 드러냈습니다.** 저희가 7/31에 넣은
"시세 결손 행 후순위" 정렬이, `DUAL_FLOW`에 price가 0이던 동안은 그 행들을 뒤로
밀어주고 있었습니다. 이제 시세가 채워져 그 분기에 안 걸립니다.

→ **`min(score, 100)`으로 맞춰 주십시오.** 두 계보가 같은 척도가 되면 이 편중은
   저절로 풀립니다. 상한을 넘기는 가중치가 의미가 있다면, 정규화 방식을 알려주시면
   웹에서 반영하겠습니다(임의 추정은 하지 않겠습니다).

### ② `signal_type` 라벨 — 한글 계보로 통일

`DUAL_FLOW` 영문 enum이 들어옵니다. 정보봇 계보는 한글 3종
(`외국인+기관 동시유입` / `외국인 연속유입` / `기관 연속유입`)입니다.

**화면 노출 위험은 웹에서 이미 막았습니다** — `flowKind()`가 의미로 접어
`DUAL_FLOW` → **'쌍끌이 흐름'** 배지로 렌더합니다. 영문이 사용자에게 새지 않습니다.
다만 이건 웹 쪽 흡수이고, 새 enum이 추가되면 다시 사각이 생깁니다.

→ 한글 3종으로 맞춰 주시면 웹의 흡수 분기를 걷어낼 수 있습니다.
   유지가 필요하시면 **enum 목록을 계약으로 고정**해 주십시오(추가 시 사전 통보).

### ③ `source` 컬럼 신설 — 구조적 정공법 (정보봇 제안, 웹 동의)

같은 `(date, ticker)`를 두 산출물이 공유하는 한 UPSERT 충돌은 계속됩니다.
가드로 잡아도 **덮어쓰기 자체는 막지 못합니다**(정보봇은 "맞불이 된다"며
되돌리기를 하지 않기로 했고, 저희도 그 판단이 옳다고 봅니다).

→ `source` 컬럼 추가 후 **`(date, ticker, source)` 유니크**로 전환.
   웹은 이후 계보별 균형 노출로 바꾸겠습니다(현재는 한쪽 독점).
   3봇 합의가 필요한 스키마 변경이라, **동의 여부만 회신** 주시면 저희가 정보봇과
   일정을 맞추겠습니다.
